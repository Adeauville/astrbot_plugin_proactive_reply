**AstrBot 智能自主回复插件** —— 让机器人从"被动等 @"变成"会主动聊天"。

一个为 AstrBot 打造的「主动回复」插件：**非定时**、**自动联系上下文**、**能识别群聊非 @ 消息并自行判断对话是否还在继续**、自主决定要不要回复；私聊长时间没联系还会**主动发消息关心你**。兼容 QQ 官方接口（qq_official）等平台，配合其他插件的人设使用效果最佳。

---

## 功能特性

| 功能 | 说明 |
| --- | --- |
| 私聊 / 群聊独立自主回复开关 | 两个场景分别控制，互不影响 |
| 群聊非 @ 消息识别 | 开通 QQ 官方「读取群内全部消息」权限后，群里不 @ 机器人也能收到并自主回复 |
| 上下文延续判断 | 由 LLM 自行判断消息是否在与你对话：点名你、延续话题、刚被你回复过的人、新问题新信息 → 回；重复话题、无关闲聊 → 不回 |
| 自动联系上下文 | 按会话维度独立记忆（最近 N 轮），**只记录机器人参与过的对话**；历史以明文拼入 prompt，**兼容所有模型提供商**，不存在历史丢失 |
| 判断提示词可自定义 | 配置面板提供「上下文判断提示词」输入框，带默认值，可自行修改对话延续 / 重复话题的判定口径 |
| 关键词触发回复 | 消息包含任意关键词 → **必回**，且跳过无关性判断（触发即答） |
| 冷场概率 | `reply_probability` 只影响**冷群/新话题**时是否主动搭话；进行中的对话、@ 消息、关键词触发**不受概率影响，必回**，杜绝"聊着聊着就不接话" |
| 私聊主动问候 | 私聊里**长时间未聊天**（默认 3 天，可自定义 1–60 天）时，bot 主动发消息关心对方；内容由模型**按人设**生成（关心、担心近况等），本插件不注入人设 |
| 回复附带昵称 | 群聊回复末尾自动附上被回复人的昵称（`\n@昵称`），可开关 |
| 免打扰时间段 | 格式 `"22:00-9:00"`，支持多个、支持跨天；时段内可**分别控制**「自主回复」与「@回复」是否放行，且会拦截内置 AI 回复 |
| 防重复回复 | 同一会话 60 秒内相同文本自动跳过；回复前标记 `stop_event()` 阻止内置 AI 重复回复 |
| 判定文本自动丢弃 | 模型误输出"是，这条消息是在与我继续对话。"这类判断结论时，插件自动识别丢弃，不会误发 |
| 运行日志收集 | 完整运行信息写入 **AstrBot 日志**（`logs/astrbot.log`），插件目录 `logs/` 另滚动保留最近 3 份，便于排查 |
| 不注入人设 | 全程不传 `system_prompt`，人设由**其他插件或模型提供商**配置控制 |

> 群聊 @ 消息没有独立开关：非免打扰时段 **@ 消息总是回复**；免打扰时段内是否回复由「免打扰内@回复」开关控制。

## 安装

**方式一：文件夹安装**

将 `astrbot_plugin_proactive_reply` 整个文件夹放入 AstrBot 的 `data/plugins/` 目录，然后在 WebUI「插件」页点击刷新/重载。

**方式二：zip 安装**

将本仓库下载为 zip，在 AstrBot WebUI 插件页「安装本地插件」中上传即可。

安装后在 WebUI 插件卡片点击齿轮图标，按需修改配置并保存。

## 配置项说明

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `enable_plugin` | bool | true | 插件总开关 |
| `private_chat_auto_reply` | bool | true | 私聊自主回复开关 |
| `group_chat_auto_reply` | bool | false | 群聊自主回复开关（非 @ 消息） |
| `context_aware_reply` | bool | true | 上下文延续判断（模型判断是否在与机器人对话，无关不回复；仅群聊非 @ 生效） |
| `context_judge_prompt` | text | （内置默认） | 上下文判断提示词，追加在每条待判断消息后，可自行修改；模型输出 `__NO_REPLY__` 时插件不回复 |
| `reply_probability` | float | 1.0 | 冷群/新话题时主动搭话的概率（0–1）；进行中的对话、@ 消息、关键词触发不受影响，必回 |
| `only_reply_on_keyword` | bool | false | 仅关键词模式：开启后只有命中关键词才自主回复（私聊/群聊非 @ 均生效） |
| `keyword_triggers` | list | [] | 关键词列表（不区分大小写的子串匹配），命中即必回 |
| `private_greeting_enable` | bool | true | 私聊主动问候开关（长时间未聊 → 主动发消息） |
| `private_greeting_days` | int | 3 | 私聊主动问候间隔（天）：距离上次聊天**且**距离上次问候都超过该天数时，主动发送一条问候 |
| `private_greeting_prompt` | text | （内置默认） | 主动问候的生成指令（可自定义；不注入人设，内容由模型按当前会话的人设风格生成） |
| `append_nickname` | bool | true | 群聊回复末尾附带被回复人昵称（`\n@昵称`） |
| `quiet_periods_enabled` | bool | true | 是否启用免打扰时段 |
| `quiet_auto_reply` | bool | false | 免打扰时段内是否允许自主回复（私聊与群聊非 @ 消息） |
| `quiet_at_reply` | bool | false | 免打扰时段内是否允许 @ 消息回复 |
| `quiet_periods` | list | `["22:00-9:00"]` | 免打扰时间段，格式 `"22:00-9:00"`，支持多个、支持跨天（如 `22:00-7:00` 表示次日 7 点前） |
| `max_history_rounds` | int | 20 | 上下文记忆轮数（1 轮 = 用户+机器人各一条） |
| `use_session_provider` | bool | true | 使用当前会话绑定的模型提供商 |
| `provider_id` | string | "" | 指定模型提供商 ID（留空用会话默认） |
| `log_level` | string | INFO | 插件日志级别：DEBUG / INFO / WARNING / ERROR |

## 回复决策流程

1. **消息级过滤**：无文本（纯图片/语音）跳过；与 60 秒内已处理消息完全相同 → 跳过；
2. **插件总开关**：关闭 → 不回复；
3. **免打扰时段**：
   - @ 消息 → 由「免打扰内@回复」控制（默认不放行，且阻止内置 AI 回复）；
   - 自主回复（私聊/群聊非 @）→ 由「免打扰内自主回复」控制（默认不放行）；
4. **群聊 @ 消息**（非免打扰）→ 总是回复；
5. **群聊非 @ 消息**：
   - 命中关键词 → **必回**（跳过无关性判断）；
   - **延续信号**：bot 刚回复过该发送者 → 直接继续回复，不询问模型；
   - **冷场概率**：无进行中对话时，按 `reply_probability` 决定是否主动搭话；
   - **上下文延续判断**：由模型判断是否与机器人对话（无关 / 重复话题 → 不回复）；
6. **私聊** → 私聊自主回复开关 → 命中关键词必回 / 仅关键词模式 → 必回（私聊不参与冷场概率）；
7. **后台任务** → 每 30 分钟检查私聊会话，超过「主动问候间隔」未互动的会话，按人设生成并主动发送关心问候。

## 平台支持

- **QQ 官方接口（qq_official）**：需在 [QQ 开放平台](https://q.qq.com/) 为机器人开通 **「读取群内全部消息」** 与 **「主动回复 / 主动消息」** 权限。已开通后，平台会下发群内非 @ 消息，插件的群聊自主回复（非 @）即可正常生效；私聊主动问候依赖「主动消息」权限。
- **aiocqhttp（QQ 个人号）**：可接收群内全部消息，非 @ 自主回复完整生效。
- 其他 AstrBot 支持的平台（Telegram / Discord / 飞书等）同样适用。

## 运行日志

- **AstrBot 统一日志**：插件运行信息以 `[智能自主回复]` 前缀写入 AstrBot 日志 `logs/astrbot.log`（需在 AstrBot 配置中开启「日志文件输出」，即 `log_file_enable: true`），方便统一管理查看；
- **插件滚动日志**：插件目录 `logs/auto_reply.log`，单文件最大 2MB，滚动保留最近 **3 份**（当前文件 + 2 份轮换）；
- 日志记录「收到消息 / 决定回复 / 回复内容 / 不回复原因 / 主动问候发送」等完整链路，配合 `/autoreply_log` 指令即可快速排查。

## 常见问题（FAQ）

- **插件不回复**：先在配置里打开对应开关；再执行 `/autoreply_status` 核对状态；最后看 AstrBot 日志中 `[智能自主回复]` 前缀的「不回复 | 原因=…」记录，原因一目了然。
- **聊久了就不接话**：优先看日志「不回复 | 原因=…」：
  1. **开了「仅关键词模式」**：只有消息包含关键词才会回复——最常见的原因，关闭即可；
  2. **「冷场概率」太低**（如 0.35）：只影响冷群时是否主动搭话，调高（如 1.0）即可；
  3. 日志显示「上下文延续判断：该消息与机器人对话无关」：模型判定为无关，可在配置面板放宽「上下文判断提示词」（去掉重复话题拒绝规则）。
- **bot 发出"是，这条消息是在与我继续对话。"这类判定文本**：默认提示词已明确禁止输出判断过程，插件也会自动识别并丢弃各类判定确认文本；若仍出现，请把配置面板「上下文判断提示词」恢复为默认值（旧版保存的自定义提示词不会自动更新）。
- **@ 消息被回复两次 / 回复两条相近消息**：插件回复前已标记 `stop_event()` 阻止内置 AI 重复回复，并内置 60 秒相同内容去重；仍出现时请把日志中 `[智能自主回复]` 相关段落发到 issue。
- **记忆丢失**：会话记忆保存在内存中，AstrBot 重启或插件重载后清空，属正常现象。
- **私聊不主动问候**：确认已开通「主动消息」权限；插件只记录**收到过**的私聊会话（与对方聊过才会问候）。

## 更新日志

### v1.7.4（当前）
- **接入 AstrBot 原生会话历史**：调 LLM 前从 conversation_manager 加载数据库里的历史对话到 `req.contexts`，bot 能记得本插件安装之前聊过的内容，不再只靠插件自己内存里的短期记忆；
- 加载失败时静默降级，不影响回复主流程。

### v1.7.3
- 修复 master_aware（认主插件）注入不生效的问题：认主提示是通过 `req.extra_user_content_parts` 传递的，之前只传了 prompt/system_prompt 导致丢失；现在钩子跑完后把整个 `req` 对象全量传给 provider，所有通过 on_llm_request 钩子改 req 字段的插件都能正常工作；
- 插件职责收敛：只管"要不要自主回复"的决策，生成内容完全交给标准 pipeline。

### v1.7.2
- 修复 lili_state 人设不生效的根因：lili_state 不是往 `system_prompt` 里加人设，而是直接改写 `req.prompt`（为前缀缓存稳定），之前只取了空的 system_prompt；现在用钩子改写后的 `req.prompt` 作为最终 prompt。

### v1.7.1
- 修复钩子白名单过滤问题：`call_event_hook` 内部会用 `event.plugins_name` 过滤 handler，从本插件内部触发时只会跑到自己的 handler；现在临时放开为 `["*"]`，让 lili_state 等人设插件的 on_llm_request 钩子能被正确触发。

### v1.7.0
- **接通 on_llm_request / on_llm_response 钩子链**：插件自己调 LLM 前后手动触发 AstrBot 的标准钩子，让 lili_state（莉莉状态管理）等人设插件能正常注入人设并维护状态；钩子不可用时自动降级为旧行为。

### v1.6.0
- 「回复概率」改为**冷场概率**：只影响冷群/新话题时是否主动搭话，进行中的对话、@、关键词触发必回，彻底解决"聊着聊着不接话"；
- 新增**私聊主动问候**：长时间未聊天（默认 3 天，可自定义）主动发消息，内容按模型人设生成（不注入人设）；后台每 30 分钟检查，发送后自动重置计时；
- 新增**回复附带昵称**：群聊回复末尾追加 `\n@昵称`（可开关）。

### v1.5.0
- 判定确认文本识别覆盖实测格式（"是在与你继续对话。因为这条消息点名了…属于明确与你互动的新问题。"等），且所有回复路径均拦截；
- 关键词触发 = 必回且跳过无关性判断；
- 判断提示词强化违规示例说明。

### v1.4.0
- 历史以**明文拼入 prompt**，不再依赖 provider 的 contexts 参数，兼容所有模型提供商（修复"聊久了不接话"根因）；
