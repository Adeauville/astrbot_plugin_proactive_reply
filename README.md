# 智能自主回复插件（astrbot_plugin_proactive_reply）

为 AstrBot 提供「主动回复」能力：让 QQ 官方 Bot（及 aiocqhttp 等平台）在**非定时**场景下主动回复消息，
自动联系上下文，并能识别群聊中的**非 @ 消息**、**自己判断对话是否还在继续**、自主决定要不要回复；
私聊长时间未互动时还会按人设**主动问候**。

## 功能一览

| 功能 | 说明 |
| --- | --- |
| 私聊自主回复开关 | 控制私聊是否自主回复，默认开启 |
| 群聊自主回复开关 | 控制群聊**非 @ 消息**是否自主回复，默认关闭 |
| 上下文延续判断 | 让模型自动识别消息是否在与机器人对话，无关的消息不回复（仅群聊非 @ 自主回复生效，默认开启）；刚回复过的人再次发言视为对话延续，直接回复、不漏回；模型误输出「判定确认文本」（如“是，这条消息是在与我继续对话。”、“是在与你继续对话。因为这条消息点名了…属于明确与你互动的新问题。”）会被自动识别丢弃，不会误发 |
| 上下文判断提示词 | 配置面板可自定义修改判断提示词（带默认值），可控制对话延续与「重复话题不再回复」的判定 |
| 防重复回复 | 同一会话内相同内容 60 秒内重复出现自动跳过，避免同一条消息被重复回复 |
| 自动联系上下文 | 按会话维度独立维护记忆（最近 N 轮），**只记录机器人参与过的对话**；历史以明文拼入 prompt，**兼容所有模型提供商**，不会出现历史丢失 |
| 自主选择是否回复 | 群聊非 @ 消息在**冷群/新话题**时按「冷场概率」随机决定是否主动搭话；正在进行的对话（刚回复过对方）、@消息、命中关键词**必回** |
| 关键词触发回复 | 配置关键词列表，消息包含任意关键词即触发回复 |
| 仅关键词模式 | 开启后，只有命中关键词才自主回复（私聊/群聊非 @ 均生效） |
| 私聊主动问候 | 私聊里**长时间未聊天**（默认 3 天，可自定义）时，bot 主动发消息关心对方；内容由模型按其人设生成（如关心、担心对方近况），插件不注入人设 |
| 回复附带昵称 | 群聊回复末尾自动附上被回复人的昵称（如回复内容后加一行 `@昵称`），可开关 |
| 免打扰时间段 | 格式 `"22:00-9:00"`，支持多个、支持跨天；时段内可分别放行「自主回复」与「@回复」 |
| 运行日志收集 | 完整运行信息写入 **AstrBot 日志（logs/astrbot.log）** 便于统一查看；插件目录 `logs/` 另保留最近 3 份文件日志 |

> 群聊 @ 消息没有独立开关：非免打扰时段 @ 消息**总是回复**；免打扰时段是否回复由「免打扰内@回复」开关控制。

## 安装

1. 将 `astrbot_plugin_proactive_reply` 整个文件夹放入 AstrBot 的 `data/plugins/` 目录；
2. 在 AstrBot WebUI「插件」页点击刷新/重载；
3. 点击插件卡片的齿轮图标，按需修改配置并保存。

> 也可以将本文件夹压缩为 zip，在 WebUI 插件页「安装本地插件」中上传。

## 配置项说明

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| enable_plugin | bool | true | 插件总开关 |
| private_chat_auto_reply | bool | true | 私聊自主回复开关 |
| group_chat_auto_reply | bool | false | 群聊自主回复开关（非 @ 消息） |
| context_aware_reply | bool | true | 上下文延续判断（模型判断是否在与机器人对话，无关不回复；仅群聊非 @ 生效） |
| context_judge_prompt | text | （内置默认） | 上下文判断提示词，追加在每条待判断消息后，可自行修改；模型输出 `__NO_REPLY__` 时插件不回复 |
| reply_probability | float | 1.0 | 冷群/新话题时主动搭话的概率（0–1；进行中的对话、@、关键词触发不受影响，必回） |
| only_reply_on_keyword | bool | false | 仅关键词触发时自主回复 |
| keyword_triggers | list | [] | 关键词列表（不区分大小写的子串匹配） |
| quiet_periods_enabled | bool | true | 是否启用免打扰时段 |
| quiet_auto_reply | bool | false | 免打扰时段内是否允许自主回复（私聊与群聊非 @ 消息） |
| quiet_at_reply | bool | false | 免打扰时段内是否允许 @ 消息回复 |
| quiet_periods | list | ["22:00-9:00"] | 免打扰时间段，格式 `"22:00-9:00"`，支持多个、支持跨天（如 `22:00-7:00` 表示次日 7 点前） |
| max_history_rounds | int | 20 | 上下文记忆轮数（1 轮 = 用户+机器人各一条） |
| use_session_provider | bool | true | 使用当前会话绑定的模型提供商 |
| provider_id | string | "" | 指定模型提供商 ID（留空用会话默认） |
| private_greeting_enable | bool | true | 私聊主动问候开关（长时间未聊 → 主动发消息） |
| private_greeting_days | int | 3 | 私聊主动问候间隔（天）：距离上次聊天/上次问候超过该天数才主动问候 |
| private_greeting_prompt | text | （内置默认） | 主动问候的生成指令（可自定义；不注入人设，内容按模型当前人设风格生成） |
| append_nickname | bool | true | 群聊回复末尾附带被回复人昵称（`\n@昵称`） |
| log_level | string | INFO | 插件日志级别：DEBUG/INFO/WARNING/ERROR |

## 回复决策流程

1. 消息级：无文本（纯图片/语音）或与 60 秒内已处理消息完全相同 → 跳过；
2. 插件总开关关闭 → 不回复；
3. 处于免打扰时段：
   - @ 消息：由「免打扰内@回复」控制（默认不放行，且会阻止内置 AI 回复）；
   - 自主回复（私聊/群聊非 @）：由「免打扰内自主回复」控制（默认不放行）；
4. 群聊 @ 消息（非免打扰）：总是回复；
5. 群聊非 @ 消息：群聊自主回复开关 → 命中关键词必回 / 仅关键词模式 → **延续信号**（bot 刚回复过该发送者则直接回复，不询问模型）→ **冷场概率**（无进行中对话时按概率决定是否主动搭话）→ 上下文延续判断（模型判断与机器人无关、或为重复话题则不回）；
6. 私聊：私聊自主回复开关 → 命中关键词必回 / 仅关键词模式 → 必回（私聊不参与冷场概率）；
7. 后台任务：每隔 30 分钟检查私聊会话，超过「主动问候间隔（默认 3 天）」未互动的会话，按人设生成并主动发送一条关心问候。

## 管理指令

| 指令 | 说明 |
| --- | --- |
| `/autoreply_status` | 查看当前状态与配置摘要 |
| `/autoreply_log 100` | 查看最近 100 行插件日志（默认 30 行） |

## 日志位置

插件运行日志会**同时**写入两个地方：

1. **AstrBot 日志**：经 AstrBot 日志系统输出，进入控制台与 `logs/astrbot.log`（由 AstrBot 全局日志配置控制），统一在这里排查即可；
2. **插件文件日志**：插件目录下 `logs/auto_reply.log`（单文件最大 2MB，只保留最近 3 份，即 `auto_reply.log` 及 `.1`、`.2` 轮换文件），便于单独导出，完整路径一般为：

```
<AstrBot根目录>/data/plugins/astrbot_plugin_proactive_reply/logs/auto_reply.log
```

排查问题时先看 AstrBot 日志中带 `[智能自主回复]` 前缀的记录，日志中会记录「不回复 | 原因=…」，原因一目了然。

## 人设说明

本插件**不注入任何系统提示词/人设**，回复风格由你的其他插件或模型提供商配置控制。

## 平台说明（重要）

- **QQ 官方接口（qq_official）**：需在 QQ 开放平台为机器人开通「读取群内全部消息」与「主动回复/主动消息」权限。已开通后，平台会下发群内非 @ 消息，插件的群聊自主回复（非 @）即可正常生效；若未开通，平台只推送被 @ 的消息，非 @ 自主回复无法收到消息。
- **aiocqhttp（QQ 个人号）**：可接收群内全部消息，非 @ 自主回复可完整生效。

## 常见问题

- **插件不回复**：先在配置里打开对应开关；再执行 `/autoreply_status` 核对状态；
  最后看 AstrBot 日志中 `[智能自主回复]` 前缀的「不回复 | 原因=…」记录，原因一目了然。
- **@ 消息被回复两次 / 回复两条相近消息**：本插件回复前即标记 `stop_event()` 阻止内置 AI 重复回复，并内置「60 秒内相同内容」去重；若仍出现两条相近回复，请把 AstrBot 日志（`logs/astrbot.log`）中带 `[智能自主回复]` 前缀的相关段落发给插件作者核对，日志里会记录每条「收到消息 / 决定回复 / 回复内容」，可直接判断是同一条消息被处理两次，还是两条不同消息各回一次。
- **聊久了就不接话**：优先检查插件运行日志（插件目录下 `logs/auto_reply.log`）里的「不回复 | 原因=…」。常见原因：
  1. **开了「仅关键词模式」**（`only_reply_on_keyword` 开启）：只有消息包含关键词才会回复，普通对话全部不接——这是最常见的原因；关闭它即可恢复自主回复；
  2. **「冷场概率」太低**（如 0.35）：只影响没有进行中对话时的主动搭话，调高（如 1.0）即可；
  3. 日志显示「上下文延续判断：该消息与机器人对话无关，不回复」：模型判定为无关，可在配置面板调整「上下文判断提示词」（去掉重复话题拒绝规则或改宽松）。
- **bot 发出“是，这条消息是在与我继续对话。”“是在与你继续对话。因为这条消息点名了…”这类判定文本**：v1.5.0 起默认提示词明确禁止输出判断过程，且插件会自动识别并丢弃各类判定确认文本（含“是在与你继续对话…”“这条消息点名了…属于明确与你互动的新问题”等格式）；若仍出现，请在配置面板把「上下文判断提示词」恢复为默认值（旧版保存的自定义提示词不会自动更新），或把提示词内容发给插件作者。
- **关键词触发的含义**：消息包含「关键词触发列表」中的任意词时，**必回复且跳过上下文无关性判断**（触发即答，不输出判断文本）；未命中关键词时，按「自主回复概率」+「上下文延续判断」决定是否回复。
- **记忆丢失**：会话记忆保存在内存中，AstrBot 重启或插件重载后清空，属正常现象。
